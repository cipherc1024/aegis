架构与信任边界

页面上的每个数值都来自 orchestrator 的只读端点或链上公共 RPC。取不到就显示「离线」——本页不编造任何数字。

信任边界：谁握着什么
Proposer 机器（本机）
proposer
双 LLM 管线 + 确定性 δ 预览；持有 TEE 私钥，可提交收据。⚠️ 同一地址当前也是链上金库 owner（见下方「密钥现状」）
持有 MONAD_TESTNET_PK
Challenger 机器（独立）
challenger
独立钱包上链 validation；verify.mjs 只依赖 ethers + 自己的 objective.mjs（单向零依赖）；可选跨家族模型层默认关闭（非 L5，L5 专指目标层）
持有 CHALLENGER_PK
Phala CVM（TDX）
tee
实时生成绑定 digest 的 TDX quote，链上 DCAP 验真
无私钥
密钥现状（如实披露）链上金库 owner、TEE 执行地址与 proposer 签名地址当前是同一个地址（见 /subaccounts 或链上 owner() / teeDerivedAddress() / registry.agentTEE(1)）。因此严格成立的表述是——Agent 无法执行一笔未经 challenger 背书的交易；而金库治理权（withdraw / setLimits / setTarget / setReceiptRegistry / setTrustedValidator）目前集中在单一密钥上，该钥单独即可提空金库或更换收据表以绕过 quorum 闸门。生产化拆分路线：owner 多签 + governance timelock + TEE 独立 HSM/独立主机。
