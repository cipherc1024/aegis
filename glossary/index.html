术语表

本项目大量使用自造缩写。这一页给每个术语一句话定义，并标出常见的误读——读其他页面前先扫一眼，能省很多时间。

安全判据（真正的边界）
δ（确定性谓词）
整套安全判据的统称：护栏 + PACE + 目标层。它就是安全边界；LLM 的输出只是被它分类的不可信输入。
常见误读：常见误读：以为「TEE 里的模型」提供保证。保证来自 δ 被正确求值，与模型是否可被操纵无关。
护栏（Guardrail）
对可信指令与外部内容做归一化（去零宽字符、leet 折叠、大小写）后匹配注入模式与黑名单。
常见误读：proposer 预览与 challenger 必须同口径，否则会造出假性分歧；parity-check 就是守这个的。
PACE
策略约束层：目标白名单 + 单笔上限 + 日限（含当日已用额度）。链上与链下同口径。
目标层 / L5（SOA-lite）
用户用 EIP-191 签署一个客观目标（金额区间、标的、期限、nonce），而不是一个动作；challenger 独立验签并做 ε-区间检查。
常见误读：于是「策略合规」不等于「你授权的」：意图漂移即使通过 PACE 也会被 L5 拒。注意 L5 指目标层，与可选的交叉模型层不是一回事。
L1–L5（challenger 五层）
策略认证 / 独立护栏 / 独立 PACE（含日限）/ 算术与原文 preimage 绑定 / 目标层验签 + ε。全部确定性，不 import proposer 任何模块。
哈希与绑定链
executionHash
keccak(target, value, calldata)。金库放行的判据就是它必须与最近一张交易收据里的值逐字节相同。
PDR / pdrHash
keccak(executionHash, guardrailHash, true)：把「执行什么」与「当时哪套策略」绑在一起。
semantic digest（收据摘要）
把 agentId、nonce、prev 与上面的哈希编码成 64 字节，作为 TDX quote 的 report_data。
哈希链 / prev
每张收据引用上一张的 digest。删一条、换顺序、回滚都会在重算 digest 时暴露。
blockhash 绑定 / MAX_BLOCK_AGE
收据须声明它基于哪个区块，链上校验 blockhash(blockHeight) 且不超过 100 块——防分叉重放。
nonce / 防重放
per-agent 的 usedNonces；同一张收据不能提交两次。
身份与硬件证明
TDX quote / DCAP
Intel TDX 硬件签名的证明，含运行环境度量值；DCAP 是验证它的协议栈。本项目在链上验，不是离链验。
CVM / dstack
Phala 的机密虚拟机（TDX），以及它在容器内提供 quote 的运行时套接字。
report_data
quote 里留给调用方的 64 字节。这里放 semantic digest，把「这份决策」与「这个运行环境」钉在一起。
TEE 信任边界
TEE 只回答谁在什么环境跑，不回答决策对不对；后者由 challenger 回答——两个正交维度。
常见误读：LLM 刻意跑在 TEE 之外：把可被操纵的东西放进 enclave 只保护它的机密性，不产生「决策正确」的保证。
执行闸门与状态
quorum 闸门 / _preExecutionHook
executeTrade 前的链上检查：验证者地址必须在金库 owner 白名单内，且它对最新交易收据 digest 给出的 response ≥ 100。
常见误读：ValidationRegistry 本身无需许可，所以只读分值是错的：任何人都能自证自答伪造 quorum。
isTradeFresh / isAlive
前者看最新交易收据是否在 MAX_BLOCK_AGE 内；后者看最近任意收据是否在 STALENESS_LIMIT 内（存活）。
死手开关 / tradingFrozen
agent 长时间没有新鲜收据时，任何人可调 freezeIfStale 冻结交易；owner 可 resumeTrading（需先有新鲜收据）。
常见误读：侧边栏的「收据不新鲜」不等于「已冻结」：前者只说明条件已满足，链上 tradingFrozen 可能仍是 false。
角色与标准
proposer / challenger
proposer 是出主意的 agent 进程（双 LLM 管线 + δ 预览，持收据提交钥）；challenger 是独立裁判进程，持另一把钥，独立重推导后上链裁决。
owner / TEE 派生地址
owner 是金库治理钥（withdraw / 限额 / 白名单 / 换 registry / 授权验证者）；TEE 派生地址只被允许执行通过全部关卡的字节。
常见误读：当前部署里 owner == TEE 派生地址 == proposer 签名地址（同一把钥），已在总览页如实披露：不要在答辩中声称三方分权。
ERC-8004
身份 / 声誉 / 验证三个注册表。本项目自部署（官方 testnet 无部署），并把 Validation 从元数据改造成执行硬闸门。
输入真实性不可能性（R1）
谓词只能验证「给定输入 x 的决策」，无法验证 x 本身未被代换。这是不可能性边界，实验里作为负对照公开。
